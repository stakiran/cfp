# cfp セキュリティ調査（2026-10-03）

キーロギングなどのリスクがないかを、3つのセキュリティペルソナで分担して調べた。

- マルウェアアナリスト
- プライバシーエンジニア
- AppSec／サプライチェーン

読み取りだけで調べ、ビルドも実行もしていない。

## 結論

キーロガーになっている心配はほぼない。3人とも同じ結論だった。

打った内容（キーコード・文字・打った順序・打鍵間隔の生データ）を残したり外に送ったりする処理は、どこにもない。残るリスクは次の2つ。

- 記録される「いつ・どれだけ操作したか」のデータ（メタデータ）
- exe や DB の置き方・実行権限

## キーロガーではないと言える根拠

- **キーの値はその場で捨てている**: キーの識別子（VKey）は `main.rs:217` から `collector.rs` の `on_key` に渡る。使われるのは、文字キー・Backspace などの種類への分類と、「今押されているか」の判定（`pressed[256]`）だけ。カウンタを増やしたら値は捨てられる。
- **MakeCode の用途は1つだけ**: 偽の Shift を除外する判定（`main.rs:213`）にしか使っていない。
- **文字に変換していない**: 打ったキーを文字に変換する処理（ToUnicode や WM_CHAR の処理）はない。
- **外部とのやり取りがない**: 通信、プロセス起動、レジストリ、クリップボード、前面アプリやウィンドウタイトルの取得、スクリーンショット、キーボードフック（SetWindowsHookEx）は、どれも使っていない。
- **書き込むのは DB だけ**: ファイルへの書き込みは `cfp.db` と、その WAL/SHM ファイルだけ。
- **依存関係に怪しいものはない**: Cargo.lock の 39 パッケージのうち、cfp 自身を除く 38 件がすべて crates.io から取得したもので、checksum 付き。git や path から取るクレートも、タイポスクワットらしき名前もない。
- **SQL インジェクションの余地がない**: SQL はすべてパラメータ化されている（`store.rs`）。
- **README と CONTEXT.md の約束はコードと一致している**: 「キーコード・文字・座標・アプリ名を保存しない」「打鍵間隔は4段階に丸める」「自動リピートは数えない」は、実装でも守られている。

## 残るリスク（重要度の高い順）

| 重要度 | 内容 | 指摘したペルソナ |
|---|---|---|
| **中〜高** | **管理者権限で実行する場合**: README は管理者実行に触れている。exe がユーザーが書き込めるフォルダ（`target\release`）にあると、DLL の差し替えや exe 自体の差し替えで、マルウェアが管理者権限を得る足がかりになる。 | AppSec |
| **中** | **少し改変すれば本物のキーロガーになる**: `main.rs:132,139` で `RIDEV_INPUTSINK` を指定しているので、cfp が前面にないときも全アプリのキー入力が届く。`on_key` にログを1行足すだけで完全なキーロガーになる。これは Raw Input の性質なので、コード側では防げない。 | 3人全員 |
| **中** | **在席状況と生活リズムの記録になる**: 入力ゼロの10秒も保存するので、出退勤・休憩・睡眠の時刻が連続して残る。打鍵速度や打ち間違いの率の変化から、疲労や体調も推測できる。CONTEXT.md の「個人情報は含めない」は言い過ぎ。 | プライバシー |
| **中** | **パスワードの長さが推測できることがある**: 無入力のあと「文字 N 個 + Enter」だけの10秒があれば、パスワードの桁数が N だと推測できる。内容は分からない。 | マルウェア、プライバシー |
| **中** | **DB の置き場所と管理**: 暗号化されておらず、保持期限もない。exe と同じフォルダに置かれるので、OneDrive などの同期フォルダに exe を置くと DB もクラウドに上がる。共有フォルダに置けば、別のユーザーも同じ DB に書き込む。`store.rs:49` が `INSERT OR REPLACE` なので、そのときは互いの行を上書きする。 | プライバシー |
| 低 | **同梱の SQLite が古い**: rusqlite 0.31 に同梱の SQLite は 3.45.0 で、その後の CVE は未修正。ただし外部から SQL が入らない作りなので、影響は小さい。 | AppSec |
| 低 | **多重起動防止を邪魔できる**: ミューテックス名 `Local\cfp-collector`（`main.rs:78`）を他のプロセスが先に作っておくと、cfp は何も表示せずに起動しなくなる。 | AppSec |
| 低 | **記録中かどうかが分かりにくい**: トレイアイコンは汎用の `IDI_APPLICATION` で、メニューは「終了」だけ。一時停止がない。 | プライバシー |
| 低 | **行動生体情報としての識別性**: 4段階ヒストグラム自体の識別力は弱い。ただし数週間分の Backspace 率・マウス速度・持ち替え回数を合わせると、少人数の中から人を見分ける程度の弱い識別はできる可能性がある。 | プライバシー |
| 低 | **注入された入力も数える**: パスワードマネージャーの自動入力（SendInput）も、手で打った入力と区別せずに数える。`hDevice` を確認していない。 | プライバシー |
| 低 | **shell:startup による自動起動**: ユーザー権限で書ける場所なので、ショートカットの差し替えで永続化の足がかりになる。ただし同じ権限を持つ攻撃者はもともと何でもできるので、上乗せされるリスクは小さい。 | AppSec |
| Info | DB への挿入エラーを `let _` で無視している（`main.rs` の insert 呼び出し）。 | マルウェア、AppSec |
| Info | `view.py:46` の `file:{db}?mode=ro` は、パスに `?` や `#` が含まれると壊れる。 | マルウェア、AppSec |
| Info | ロック画面・UAC 画面や他のセッションの入力は、Raw Input の仕組み上届かない。ただし RDP クライアントで遠隔先に打ったパスワードは、手元の入力として数えられる。 | プライバシー |
| Info | Raw Input は低レベルフックより目立ちにくい。それでも「隠しウィンドウ + INPUTSINK + 自動起動 + 署名なし」はキーロガーの典型パターン（MITRE T1056.001）に当たるので、ウイルス対策ソフトに誤検知される可能性がある。フォルダごと除外に入れると、同じ場所に置かれた本物のマルウェアも素通りするので避ける。 | AppSec |

表の主な指摘（`RIDEV_INPUTSINK`、`INSERT OR REPLACE`、ミューテックス名、通信やプロセス起動の処理がないこと）は、統括側でもソースを見て確認した。

## 対策の候補

1. 管理者権限では実行しない。どうしても必要なら、exe を `C:\Program Files` 配下（管理者しか書けない場所）に置く。
2. DB の保存先を `%LOCALAPPDATA%\cfp` に移し、本人だけが読めるアクセス権にする。保持期間を決めて、古い行を自動で消す。
3. トレイメニューに「一時停止」を追加する。パスワード入力の前に止められるようにするため。
4. CONTEXT.md の「個人情報は含めない」を「入力内容は含まないが、活動の時系列は記録される」に直す。
5. rusqlite を新しいバージョンに上げる。
6. 細かい対策:
   - `INSERT OR IGNORE` にする。
   - ミューテックス名にユーザー SID を含める。
   - 注入された入力（`hDevice == 0`）を除外する。
   - `cargo build --locked` と `cargo audit` を習慣にする。
